Docs are how OASA shares what it knows. Fixing a doc counts as contribution.

  : <p>The edit link appears on each page once the repository is public.</p>}

## House style

Short, clear, not wordy. Using AI to help write is encouraged. Then cut anything wordy.

## Owners and reviews

Each doc has an owner and a "last reviewed" date. A doc is flagged for review after a year.

## When to write a doc

If a question is answered twice in Discord, it becomes a doc.

## Templates

Charter, build guide, BOM, test report, lessons learned, decision record, standard spec and course outline.

## Working on the tech tree

Pick an available node and comment `/claim` on its issue. See [claim a node](/docs/claim-a-node/).

## Ideas

<p>Post ideas on the <a href="/ideas/">ideas page</a>. Every idea gets a number (IDEA-0042 and so on) and is sorted onto the tech tree. You can also start a post in the Ideas discussions; it's copied over within the hour.</p>

Also see [projects](/docs/projects/) and [standards](/docs/standards/).
