Every piece of OASA work follows the same five steps, whether it's code, a CAD model, a test, a document or an event.

**Pick → say so → do it in the open → get a review → close it.**

## 1. Pick something

| Where work lives | What it is |
|---|---|
| [Tech tree](/techtree/) nodes | The big map: each node is a capability OASA is building |
| [Task cards](https://github.com/search?q=org%3Ajoinoasa+is%3Aissue+is%3Aopen&type=issues) | Smaller jobs as GitHub issues. `agent-ready` ones an AI agent can finish with you |
| [Ideas](/ideas/) | New ideas, before they're on the tree |
| Your own project | [Register it](/docs/projects/) so others can find and join it |

Not sure? Ask your buddy or in Discord for a first task that fits your skills.

## 2. Say you're taking it

So nobody duplicates your work:

- **A tech tree node:** comment `/claim` on its issue ([how](/docs/claim-a-node/)).
- **A task card or anything else:** comment "I'm taking this" on the issue. If there's no issue yet, open one.

## 3. Do the work in the open

| Kind of work | Where it goes |
|---|---|
| Code, docs in repos | A branch and a pull request in the repo ([contributing](/docs/contributing/)) |
| CAD, hardware files, test data, photos, video | The [shared drive](https://share.joinoasa.org), in `Projects/<node ID> <name>/` |
| Writing you edit with others | The shared drive for now; Google Drive once OASA's Workspace is set up |
| Questions and quick decisions | Discord, then a short note on the issue so it isn't lost |

Post a short update on the issue each week, even if it's "still working on X".

## 4. Get a review

Nothing is done until someone else has looked at it.

- **Code:** open a pull request. The checks run and a person reviews it. Tick "AI-assisted" if an agent helped.
- **Everything else:** post the link (drive folder, document, photos, results) on the issue and ask your mentor or the project lead to review it.

## 5. Close it

The reviewer approves and the issue is closed (a pull request closes it when it merges). Finishing a node unlocks the next ones on the tree, and your work is credited on the issue.

## Ground rules

- **No secrets** anywhere: no passwords, keys or tokens in issues, files, Discord or the drive.
- **No personal data** about other people in issues or files.
- **One topic per issue or pull request.**
- **Stuck for more than a couple of days?** Say so on the issue. Asking early is normal here.

*Coming soon:* a task board (Jira) for admin and non-code work, kept in sync with GitHub. Until then, GitHub issues are the one place work is tracked.
